Task 0009 is done, owner opencode-media-20261110. `internal/store` embeds the ordered migration set (baseline 0001_schema.sql; files are append-only after committed use) and applies each migration exactly once in its own transaction together with its `schema_migrations` ledger row, so a failing migration rolls back completely and leaves the previous schema and data intact; a ledger newer than the embedded set is rejected without downgrading. Normal startup (`Open`) now enforces the schema boundary: missing, pending, or newer schemas are rejected with distinct errors and guidance and never hot-upgrade under a running handle.
